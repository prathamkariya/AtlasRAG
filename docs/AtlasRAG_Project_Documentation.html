01 The research question

Does adaptive retrieval routing provide consistent benefits for scientific-literature QA, or are its gains concentrated in particular question types and evidence structures?

Narrower and more testable than the original framing — and honest about what is and isn't new (see §2).

02 Positioning — what's actually novel

Adaptive query-complexity routing is established prior art. It is not a new idea, and this project does not claim otherwise.

This is grounded in and explicitly builds on:

  • Adaptive-RAG (Jeong et al., 2024) — a small classifier routes queries among no-retrieval / single-step / multi-step strategies by predicted complexity. Structurally the same idea as Compass V1.
  • Self-RAG (Asai et al., 2024) — retrieval decisions embedded in generation via reflection tokens.
  • FLARE (Jiang et al., 2023) — generation-probability signals as the retrieval trigger.
  • RAGRouter-Bench (2026) — notes that classifier-based routing is now settled; differentiation comes from domain and implementation.
  • RouteLLM, FrugalGPT, RouterBench, Hybrid LLM — same paradigm applied to model selection; cited for the cost/quality framing Compass borrows.

The defensible contribution is not the routing mechanism. It is:

  1. Applying it to scientific literature — multi-paper conflicts, temporal supersession, tables/equations — a setting existing adaptive-RAG benchmarks mostly don't test.
  2. A failure taxonomy specific to scientific evidence (§8.3).
  3. A stratified evaluation testing whether routing helps uniformly or only for specific question types (H4, §7).
  4. An Oracle ceiling analysis (§6) quantifying real headroom on this domain.

Required wording, everywhere this project is described

"Compass implements and extends the adaptive retrieval-routing paradigm established by Adaptive-RAG for scientific literature, with emphasis on question-type-specific behavior and scientific evidence structure."

03 A note on Jev

Jev is not free — early access, waitlist-gated, $0.042/M input tokens, no free tier. A free-tier student project can't be built on it directly.

So AtlasRAG doesn't call Jev. We build Compass — a frozen small base + LoRA adapter + lightweight scoring head, the publicly documented Kev-style recipe. Fully open, fully free, fully ours.

04 Compass V1 — reduced scope

Compass V1 has one job: query routing.

"What is the main finding of this paper?"SIMPLE · confidence 0.94
"Compare the evidence for X across these papers."MULTI_HOP · confidence 0.87
With routing as the only variable, the experiment stays clean: does adaptive routing itself help? Evidence verification and failure prediction are deferred to V2/V3 (§10) — not built in parallel.

07 Hypotheses

  • H1 — Adaptive retrieval improves answer quality on complex scientific questions vs. a fixed strategy.
  • H2 — Compass can approximate an LLM router at substantially less computation.
  • H3 — Confidence-based escalation reduces expensive LLM calls while maintaining a quality threshold.
  • H4 — The benefit of adaptive routing is concentrated in particular question types and evidence structures, not uniform.
H4 is the project's best shot at a genuinely new finding — it's the one dimension the prior-art papers in §2 don't test on this domain.

08 Benchmark design

8.1 Metrics

CategoryMetric
Answer qualityCorrectness, relevance
Retrieval qualityContext precision, context recall
GroundingFaithfulness score
EfficiencyLatency (p50/p95), LLM calls, tokens, $/query
Routing qualityAccuracy vs. gold path, per router (C/D vs. E)

8.2 Question set — stratified by type

  • Simple factual lookup
  • Multi-hop (2+ papers)
  • Conflicting findings
  • Temporal (superseded results)
  • Abstract → methods → results chains

Every metric is reported overall and broken down by these five categories — this is what tests H4.

8.3 Gold evidence (for Oracle and later V3)

Retrieval failure occurs when the retrieved evidence does not contain sufficient information to answer the question correctly.

8.4 Benchmark honesty

Rankings have been shown to flip between two identical runs of a benchmark from ordinary variance. Run every comparison twice before trusting it.

10 Cloud / DevOps — infrastructure from day one, not a research variable

Built in from the start, but it stays infrastructure — never something the research question depends on.

In V1, from Week 1

  • Containerized from day one — docker-compose with separate services for retrieval, Compass, and the LLM gateway. All five experiments run from the same containers; only the router swaps.
  • Experiment tracking from day one — every run and rerun logged to Weights & Biases.
  • API exposed from day one — a thin FastAPI layer; a callable service from the first working version, not just a notebook.
  • Reproducible deployment — pinned dependencies, one docker-compose up reproduces the full benchmark.

Deferred to a later, explicit extension

Kubernetes (k3s on Oracle Always Free), canary rollout, drift detection, CI-gated regression testing. Still on the long-term roadmap — just not allowed to delay or become the research in §1.

14 FAQ

Is this novel, or a replication?

Both. The routing mechanism replicates Adaptive-RAG's established pattern. The contribution is applying it rigorously to scientific literature with a stratified evaluation and Oracle ceiling analysis the prior-art papers don't run on this domain.

Do we use Jev?

No — paid and waitlist-gated. We build Compass instead, free and fully ours.

Why five experiments, not four?

The Oracle answers a different question than the others — not "which router is best" but "how much is there to gain from routing at all." Without it, a weak result is ambiguous between "routing doesn't help" and "our router is bad."

Does the Docker/API/tracking layer slow down the research?

No — it's lightweight by design. Kubernetes-scale infrastructure is what's deferred, not basic reproducibility tooling.

What if H1–H3 come back negative?

Still a real, reportable result — a well-run negative finding with a solid Oracle analysis is more credible than an inflated positive claim.
